# 公司信息、范围与时间尺度

## 一、先确认真正的决策问题

用一句话复述本次任务：谁要基于报告决定什么。区分政策扫描与公司专属分析：前者描述政策环境，后者必须证明公司暴露和政策传导。

先按入口选择模式，问询与研究范围随模式调整：

- **简单单政策**：已有文件、法域和明确问题时直接核验；只补适用对象、关键日期等会改变答案的信息，不要求集团全景底稿。
- **完整扫描**：建立公司暴露、重点法域、决策目标与时间范围；复杂或不明时才展开下列问询和范围表。
- **更新**：确认基线版本、原截止日、新截止日及公司暴露变化；优先复查变化影响的主张，未复核部分保留原日期与状态。基线不可得时不能声称完成增量比较。

## 二、紧凑问询

复用用户已给信息，只补问会显著改变结论的内容。按需要从以下五组选择，不要求一次问齐：

1. **公司与业务**：产品、服务、商业模式、产业链位置、关键资质。
2. **运营地域**：注册主体、销售、生产采购、数据托管与处理、员工和资金所在地。
3. **风险暴露**：主要收入/成本、客户、供应商、牌照、政府采购、投资和税务所在地区；可提供比例或高/中/低。
4. **决策目的**：董事会简报、日常监测、市场进入、合规整改、预算、投资或政府沟通。
5. **时间尺度**：回看期、前瞻期、报告截止日和关键决策日期。

若用户已有附件或授权内部资料，再确认哪些信息可用于报告、哪些仅作背景、哪些不得外部检索或披露。

## 三、默认值

完整扫描在用户未指定时使用：

- 回看期：报告截止日前 3 个月；
- 前瞻期：报告截止日起 6 个月；
- 重大事项例外：虽超出默认区间，但仍持续影响公司时可纳入，说明原因；
- 输出：Markdown；
- 读者：管理层和公共事务为主，兼顾法务、财务；
- 覆盖：按公司实际暴露选取重点法域，不承诺穷尽全球。

使用绝对日期，不只写“近期”“下半年”“未来几个月”。

单政策围绕文件版本、当前有效状态和用户问题确定时间尺度；更新围绕基线到新截止日核查增量，必要时检查持续有效的存量规则。不要把默认 3/6 个月机械套在这两种模式上。

## 四、信息不足时不要卡死

用户暂不补充时：

1. 写明已知事实、最小必要假设和分析边界；
2. 最多列出 3 个最能改变结论的问题；
3. 按原任务提供有边界的初步解读或环境扫描，不因公司信息不足自动扩大任务，不称为已核验的公司专属结论；
4. 不虚构收入、市场份额、门店、主体、牌照、供应商或数据流；
5. 对无法判断的公司影响标记 `[Q] 待确认`；
6. 说明补充哪些事实后可升级为公司影响分析。

若用户要求“先问清楚再做”，先等答复。若用户明确要求“不要因为信息不足停住”，同一回复中完成问询、默认值说明和初步框架。

## 五、分析范围表

完整扫描可建立以下内部范围表；单政策或小型更新用简短说明即可：

| 项目 | 内容 |
|---|---|
| 决策问题 | 管理层要决定什么 |
| 重点主体 | 哪些法人、分支、合资或业务单元 |
| 重点业务 | 产品、服务、产业链环节 |
| 重点法域 | 跨国区域、国家、州省、市县区 |
| 政策主题 | 准入、税务、数据、用工、补贴等 |
| 公司暴露 | 收入、成本、许可、供应链、投资 |
| 回看/前瞻 | 绝对起止日期 |
| 关键未知 | 最多 3 项 |
| 不覆盖事项 | 主动说明 |

## 六、公司近期动态

只检索会改变政策暴露的动态：

- 新市场进入、退出或重大区域调整；
- 投资、工厂、门店、数据中心或供应链变化；
- 并购、融资、重大合同或政府客户；
- 新产品、业务模式或组织架构变化；
- 牌照、处罚、诉讼和监管沟通；
- 公司正式披露的重大经营调整。

优先公司官网、监管申报和交易所公告。若未检索到可核验动态，记录已查信源、查询词与截止时点；未检索到不代表公司没有变化，不用低质量消息制造“近期变化”。用户陈述与内部资料只作为注明来源的公司输入，公开经营事实另行核验。

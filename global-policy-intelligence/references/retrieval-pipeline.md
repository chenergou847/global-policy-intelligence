# 检索流水线：从「看见标题」到「拿到可引用的正文」

本文件是第三步（按证据等级检索并核验）的**执行细则**。它解决一个具体问题：

> 网页读取工具经常只能拿到标题、摘要或 JS 骨架页。**拿不到正文时，绝不能写出结论。**

核心矛盾不是"能不能搜到"，而是"搜到了什么级别的材料"。因此本流水线把
**检索结果分级**，并让**结论强度由材料级别决定**，而不是由模型的把握程度决定。

---

## 一、七层流水线（每层必须有明确产出）

| 层 | 名称 | 必须产出 | 失败时的行为 |
|---|---|---|---|
| L0 | 源导航 | 本次分析的信源清单（含官方公报/法规库/监管动态/统计） | 信源表落盘复用，不靠临场搜索发现信源 |
| L1 | 分级抓取 | 每条 `fetch_method`（api/feed/text/html/pdf/render/mirror） | 逐级回落，超预算即降级并留痕 |
| L2 | 完整性判定 | 每条 `fetch_status` 四态 + 首尾各 200 字指纹 | 非 full 一律不得支撑核心结论 |
| L3 | 元数据抽取 | `title/docno/issuer/pub_date/effective_date/status` | 关键字段缺失 → 该条不得作 L1 引用 |
| L4 | 核验 | 证据台账 19 字段 + 逐字引文 + 快照哈希 | 缺任一项 → 只能进"检索过程说明" |
| L5 | 存证 | 本地快照（正文 + 抓取时间 + 哈希） | 无快照 = 无法复查 = 不得引用 |
| L6 | 降级交付 | 未取得正文的来源单独成章 | 绝不混入结论，也不静默省略 |

**工具已就绪**：`tools/collector/` 实现了 L1–L5；`tools/tests/` 有离线回归；
`tools/collector/verify.py` 实现 L4 的确定性校验（C1–C4）。也可以只靠
Agent 自带的搜索/网页读取工具手工执行本流水线——规范不依赖具体工具。

## 二、源清单：信源是一等公民

**反模式**：每次任务现场搜"某国 数据保护 新规"，然后据此下结论。
**正确做法**：维护一份声明式信源表，每个信源写清"从哪里取、怎么取、失败了算什么"。

每个信源至少声明：

```yaml
- key: nfra_dongtai                    # 稳定标识
  name: 国家金融监督管理总局·监管动态
  region: 境内                          # 境内 / 境外
  layer: L1                            # L1 原始权威 / L2 官方解释 / L3 高可信二手
  probe: verified                      # verified / partial / unverified（实测状态，不许假装）
  enabled: true
  type: json_api                       # json_api|json_get|post_json|html_list|rss|sitemap
  listing:
    url: "https://…/data_itemId=915,pageIndex={page},pageSize=18.json"
    pages: 1
    rows_per_page: 18
    quirks: "pageSize 有白名单，必须为 18，其他值 404"
  extract:                             # 字段映射，支持 'a|b|c' 回落链
    records_path: "data.rows"
    title_field: "docTitle"
    date_field: "publishDate"
    docno_field: "documentNo"
    link_template: "https://…/ItemDetail.html?docId={docId}&itemId=915"
  detail:
    mode: json_api                     # json_api|html|text|pdf|render|blocked
    api_url: "https://…/SelectByDocId/data_docId={docId}.json"
    body_field: "docClob"
    content_selectors: ["div.detail_content", "div.TRS_Editor", "div#zoom"]
    tiers: [api, text, html, pdf]      # 回落链顺序
  min_body_chars: 200                  # 低于此长度不算正文
  human_assist: false                  # true = 需人工浏览器
  notes: "正文与文号可一次取全，性价比最高的信源"
```

### 为什么必须有 `probe` 字段

`probe` 记录**该信源是否被实测验证过**。这一步是诚实的载体：

- 写 `unverified` 的信源，采集时照常尝试，但报告中不得声称"已覆盖该来源"；
- 写 `blocked` 的信源（如 Cloudflare 拦截），**保留在表里**而不是删掉——
  这样报告必须写"该监管机构本期未取得正文"，而不是悄悄不提或用标题推测。

## 三、正文抓取决策树（状态机，超预算即降级）

```
① 有官方 JSON/API？           → api 级：字段结构化，最稳（优先）
② 有纯文本/XML 正文地址？      → text 级：无版式噪声
                                ※ 很多站点详情页 HTML 里**没有正文**
                                  （实测：US Federal Register 只有 raw_text_url 有）
③ 静态 HTML？                 → html 级：选择器 + 最长文本块启发式
④ URL 是 PDF 或页面含 PDF 附件？→ pdf 级：取二进制解析
⑤ 正文极短 + JS 骨架特征？     → render 级：交给渲染器（若已配置）
⑥ 仍失败？                    → mirror 级：存档镜像兜底（须用 id_ 原始内容地址）
⑦ 全部失败                    → 标 blocked + 原因 + 尝试记录
```

**每级的硬性纪律**：

1. **必须靠内容判定类型，不能靠 URL 后缀**。详情页链接可能直接返回 PDF；
   若只看后缀，就会把 PDF 二进制当"正文"存下来并标成 full——这是最隐蔽的污染。
   判据：`%PDF-` magic bytes 或 `Content-Type: application/pdf`。
2. **镜像兜底必须用原始内容地址**。默认的 Wayback 快照地址返回的是工具栏页面
   （实测仅 207 字全是短行链接，却能越过 200 字阈值被判成 full）。
3. **导航页必须能识别**。短行占比 ≥80% 且行数 ≥12 的文本，判为导航/索引页，
   降级为 `listing_only`。
4. **单条预算**：每级尝试次数与总耗时都要有上限；超限即降级并记录，不无限重试。

### 合规红线（不可越过）

| 做法 | 判定 |
|---|---|
| 读公开页面、公开 API、RSS、sitemap | 允许 |
| 声明真实 UA 与联系方式、限速、遵守 robots | 应当 |
| 抓取公开页面自身使用的接口 | 允许 |
| **绕过验证码 / 登录墙 / 付费墙 / 指纹对抗** | **禁止**：标 blocked，改走镜像或替代信源 |

对政策情报场景，"标 blocked + 说明已尝试" 的收益远高于对抗成本，且风险可控。

## 四、结论强度上限表（把防幻觉变成硬闸门）

**这是本流水线最重要的一张表**：材料级别决定你能说什么，而不是你想说什么。

| fetch_status | 含义 | 允许的表述 |
|---|---|---|
| `full` | 取得完整正文 | 可作核心结论；仍须附逐字引文 |
| `partial` | 正文被截断或缺字段 | 只能中/低置信度；须注明缺口 |
| `listing_only` | 只有标题+链接 | **只能进"信源清单/待核来源"**，不得支撑任何事实性结论 |
| `scanned_pdf` | PDF 无文字层 | 须 OCR/VLM；否则等同 listing_only |
| `blocked` | 反爬/登录墙/渲染失败 | **只能写"未取得正文"**，不得推测 |
| 模型自身知识 | 未检索 | **不得出现在任何政策事实、文号、日期中** |

补充规则：

- **来源类型 × 结论强度**：L4/L5 来源不得支撑核心法律结论；地方执行不得写成全国规则。
- **核验覆盖率必须披露**：每份报告写明 `X 条核心结论中 Y 条有正文级证据`。
- **覆盖率不足必须显式降级**：附"未取得证据清单 + 建议路径（人工浏览器/替代信源）"。
- 若判断某议题**必须先拿到正文才能负责任回答**，直接说明在该工具环境下做不到，
  而不是降级输出。

## 五、证据记账：从"我读过"到"我读到的是这些字"

### 台账 19 字段

| 字段 | 要求 |
|---|---|
| `source` / `source_key` | 来源名称与稳定标识 |
| `layer` | L1–L5 |
| `issuer` | 原始发布机关 |
| `title` | 原始标题，不杜撰译名 |
| `docno` | 文号；无则写"无/未标明" |
| `pub_date` | 原文发布日期 |
| `effective_date` | 生效日期；不适用则写"不适用" |
| `policy_status` | 已生效/待生效/草案/倡议/执法/舆情 |
| **`fetch_status`** | 四态之一（决定结论强度上限） |
| **`fetch_method`** | api/feed/text/html/pdf/render/mirror |
| **`text_chars`** | 正文字数（证明不是空壳） |
| **`snapshot_id`** | 内容哈希（检测"同链接内容变了"） |
| **`head_fingerprint` / `tail_fingerprint`** | 首尾各 200 字（最快判断是否真拿到正文） |
| `url` | 真实 URL |
| **`attempts`** | 尝试过的地址/渲染/镜像——证明"真的努力过再判无动态" |
| `notes` | 限制、缺口、失败原因 |

粗体字段是本规范新增的：它们把台账从"元数据"升级为**可审计证据**。

### 逐字引文纪律

每个核心结论必须附 **≥1 条 ≥40 字逐字引文 + 段落定位**。

- 引文必须**逐字**（可比较：忽略空白与全半角差异），**禁止改写式引用**；
- 写不出引文 → 结论自动降为 `[Q] 待确认`；
- 引文必须来自 `full` 状态的快照，且快照必须落盘。

### 数字与文号纪律

报告里出现的 `文号 / 金额 / 门槛 / 完整日期` 必须能在快照正文中找到出处。

- 归一后再比对：`2026年11月1日` ≡ `2026-11-01`；`8,000` ≡ `8000`；
- **访问日期豁免**：它是"我什么时候看的"，不是文件内容；
- 裸数字不收（政策文号里的"2026年"、期限里的"3年"都不是金额），
  只收带货币/百分比单位或有明确限定词的数值——否则误报会让校验器失去可信度。

### 去重纪律

- **URL 级**：清理跟踪参数后比对；
- **内容级**：正文哈希比对（识别跨站转载同一条政策）；
- **标题指纹级**：归一化标题 + 月份（识别同文件多版本/多语页面）；
- 冲突时保留**更完整/更权威**的一条，并把另一条记入"重复说明"。

### 多语与多版本

同一政策可能有中/英/日文页面与多个转载版本。检索指纹用
`(发布机关, 文号, 发布日期, 标题归一化)`，而不是 URL——URL 级去重解决不了这个问题。

## 六、检索失败与会话恢复

### 五态记录（每轮检索后填写）

| 类别 | 含义 | 处理 |
|---|---|---|
| 确认正面 | 找到且已核验 | 进台账，可支撑结论 |
| 疑似正面 | 找到但未取得正文 | 只作线索；列入"待核来源" |
| 空结果 | 该查询确无结果 | **必须记录已试查询词**，防止重复劳动 |
| 存在但被阻断 | 知道有文件，取不到 | 标 blocked + 原因 + 替代路径 |
| 排除 | 确认不适用 | 记入"不覆盖事项" |

### 时空覆盖

- **时间**：只用搜索引擎会带时效偏差（偏向最近、热门）。回看期必须靠
  **信源种子表 + sitemap/归档**补齐，不能只靠搜索结果。
- **地域**：用"法域覆盖矩阵"（要覆盖哪些国家/层级 × 实际取到哪些）自证，
  避免用单一市场结论覆盖全部。

### 查询矩阵

不要把"多轮检索"理解成"多试几次关键词"。系统化做法：

```
查询 = 主体 × 动作 × 客体 × 时间 × 语言/译名 × 限定
限定：site: 官方域名 / filetype:pdf / 文号 / 机构全称与简称
```

每个单元格记录命中数；**空结果也要记录**，否则"无动态"会沦为不可复查的断言。

## 七、防幻觉 12 条（可直接抄进报告流程）

| # | 机制 | 具体要求 |
|---|---|---|
| 1 | 引文先行 | 核心结论必须附 ≥40 字逐字引文 + 段落定位；写不出即降级 `[Q]` |
| 2 | 数字/文号校验 | 文号、金额、门槛、完整日期回查原文；归一后比对；不在原文即删除或标"未在原文找到" |
| 3 | 强度上限表 | 见第四节；含"模型自身知识不得作政策事实" |
| 4 | 引用四元组 | URL + 访问日期 + 快照哈希 + 文号，缺一不得进正文引用 |
| 5 | 跨源一致性 | 冲突必须并列展示并解释层级/时间/适用对象差异，禁止静默择一 |
| 6 | 知识截止 | 写明 `信息截至 YYYY-MM-DD HH:MM`，并区分"截至该时点检索到的"与"披露日已如此的" |
| 7 | 确定性用词 | 只用：已核验 / 官方表述 / 分析推论 / 待确认 / 未取得证据。**禁用**"据悉""普遍认为""据分析" |
| 8 | 自反清单 | 报告末尾固定三问：哪条只有单一来源？哪条依赖模型自身知识？哪条会因某事实变化而反转？ |
| 9 | 禁自引 | 跨报告不得引用自己此前的判断作为证据，必须回原始来源 |
| 10 | 主动反证 | 高影响结论必须写一条反证/竞争解释及判别指标；找不到要写明检索范围 |
| 11 | 双 L1 规则 | 制裁/出口管制/处罚/牌照等高危议题，单一 L1 不足以出高置信结论 |
| 12 | 失败表述标准化 | 统一写"截至 {日期}，在 {列举信源} 中未检索到…（已试查询：…）" |

## 八、可执行校验（C1–C4）

规范性要求最好能自动检查。`tools/collector/verify.py` 实现四条确定性检查：

| 检查 | 内容 | 拦截的幻觉类型 |
|---|---|---|
| **C1 引用链接** | 报告中每个来源 URL 必须在证据索引中存在 | 编造链接、"看起来很像真的"但从未访问的 URL |
| **C2 逐字引文** | `>` 引用块与「」/引号内引文必须能在快照里逐字命中 | 改写式引用、凭记忆编造条款 |
| **C3 文号数字** | 文号、金额门槛、完整日期必须能在快照里找到 | 编造文号、金额、门槛、日期 |
| **C4 证据强度** | 统计 `fetch_status` 分布；无 full 证据时判为不合格 | "只有标题却写出结论" |

用法：

```bash
python -m collector verify 报告.md --evidence evidence
python -m collector verify 报告.md --evidence evidence --json
```

**诚实边界（必须写进报告或交付说明）**：C1–C4 只能保证"你说的每个可核验事实
都真的在证据里"，**不能**判断结论方向（利好/利空）是否正确、推理是否成立。
它拦的是幻觉，不是判断错误。

## 九、量化改进：检索策略的评测集

检索质量必须可度量，否则"改进了"只是感觉。建议维护一组**故意难抓的种子**：

| 类型 | 期望行为 |
|---|---|
| JS 渲染站 | 优先找接口；否则 render 级；再失败标 blocked |
| 扫描版 PDF | 标 `scanned_pdf`，不得当正文 |
| Cloudflare 站 | 标 blocked + 原因，不得硬闯也不得假装 |
| 正文在附件里 | 走 pdf 级取到正文 |
| 纯文本接口 | 走 text 级（详情页 HTML 无正文的典型） |
| 转载站 | 内容级去重命中，保留更权威的一条 |
| 死链 | 标 blocked，附尝试记录 |
| 幻觉诱导题 | 给出"摘要可得、正文不可得"的题目，合格输出必须是"未取得正文，不出结论" |

两个主指标：

- **正文获取率** = `full` / 全部条目（目标：显著高于基线）
- **引用可核验率** = 台账中 `(url, 访问日期, 快照哈希, 逐字引文)` 四项齐全的比例（目标 100%）

再加一个**幻觉回归测试**：合不合格不看结论像不像，只看"没证据时是否拒绝出结论"。

## 十、能力边界（写进交付，别写进免责声明）

本流水线的实际能力受工具与环境限制，必须如实披露：

- 网页读取工具**不保证**能取得 JS 渲染正文、PDF 文字层、反爬页面、登录墙内容；
- 某些站点在特定网络下 TLS 握手失败（实测：本地代理对部分境内政府站失败，
  直连正常）——这是**环境问题**，不是站点没有内容；
- 因此每份报告必须给出：**核验覆盖率**、**未取得正文清单**、**建议的下一步路径**
  （人工浏览器辅助、替代官方渠道、渲染层配置）。

免责声明只说明专业责任边界；**不能用免责声明掩盖本应完成的检索**。

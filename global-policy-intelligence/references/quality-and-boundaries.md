# 质量、边界与交付检查

按任务模式和风险选择适用项。确定性校验与人工质量审查是两类检查：前者发现格式或局部证据匹配问题，后者判断主张是否成立。脚本不能替代后者，也不能证明全部人工项已通过。

## 一、交付底线

- [ ] 主张与 claims ledger 对应，核心 fact/inference 的每个 evidence URL 均对应可读 full L1/L2 快照；尚无依据的断言已撤回、缩小或列为待确认，而非只加“低置信度”。
- [ ] 事实引文、日期、数字回查的是该项 evidence；没有借其他快照里的相同数字充作依据，逐字引文保留定位，译文保留原文复核。
- [ ] 来源等级、获取状态、法律状态与具体支持关系分开；full 不证明权威性或有效性，无文号的官方文件不被机械降级。
- [ ] 假设与公司输入明示且不冒充公开事实；不能用 assumption/company 或 supporting 标签隐藏应核验的核心公开断言。
- [ ] 截止时点、适用范围、实质缺口和实际核验状态已说明；核心覆盖只计 core fact/inference，X=0 为“不适用”，不声称 100%。

以上不足时，不交付为“已核验的完整公司判断”。可以交付范围清楚的初步结果、待确认问题或证据不足判断，说明缺口影响和补证据路径；不因一项取证失败否定其他已核验内容，也不把缺证据候选伪装成已核验结论。

## 二、脚本检查及其边界

严格模式使用 `verify --claims claims.json`、`schema_version=1`，字段与运行方式见 [claims-ledger.md](claims-ledger.md)。确认实际执行了严格模式，保留运行结果；CLI 不支持或本次未运行时如实说明。

脚本可按契约检查字段、证据绑定、可读快照门槛，及 fact 引文/日期/数字在该项所引材料中的匹配。inference 检查类型与 evidence 等契约条件，正文是否清楚标注推论仍须人工核对，**不验证因果**；assumption/company 不当作公开事实核验。

即使通过，也不能证明：ledger 完整覆盖正文、来源分级正确、全文完整、引文语义、法律适用性、推理合理、判断方向正确、扫描全面或行动可行。旧模式通过也不证明逐条 evidence 绑定。交付说明区分“确定性检查通过”“人工复核结果”和“未解决事项”，不写“脚本保证所有事实正确”。

## 三、人工证据审查

- [ ] 每条重要公开事实在其所引材料中有实际依据，文本匹配之外还核对语境、否定词、主语、单位、范围、例外与版本。
- [ ] 义务、罚则、门槛和生效日期回溯 L1；官方解释、媒体报道和行业观点没有替代法规原文。
- [ ] 正文真实可读，不是二进制、验证页、导航页或镜像工具页；扫描/OCR 的关键数字与条款经核对。缺相关附件或条款时未标 full。
- [ ] 引用 URL 已实际取得，可追溯到访问/抓取时间、快照与内容哈希；无文号时记“无/未标明”，不编造。失败/待核来源与实际证据分开。
- [ ] listing_only、blocked 和未核对的扫描件只作线索；partial 不支撑核心主张。禁止平台自媒体、社评和匿名消息未进入证据引用。
- [ ] 法规状态、主管机关权限、适用对象和行政层级已核对；草案不是现行义务，个案不是全国趋势，地方执行不是全国要求。
- [ ] 关键冲突已说明版本、层级、时间或对象差异；多个转载未算作独立证据。高影响争议事项尽量交叉核验，单一来源限制已披露。
- [ ] 未检索到官方动态时记录实际信源、查询词、时点与阻断；明确不代表不存在，不推出未执法、无风险或不适用。
- [ ] 获取失败留有原因、尝试记录和可行下一步；未绕过验证码、登录墙或付费墙，未用免责声明代替检索。

## 四、人工分析与公司相关性

- [ ] 公司业务、主体、地域、暴露与决策目标来自已给信息或注明来源的输入，没有虚构收入、牌照、客户、供应商或数据流。
- [ ] 每项公司影响说明政策到行业/地方再到主体、业务、资金和时间的传导，未知暴露用条件表述，不伪装公司专属结论。
- [ ] 官方目的与分析推论分开；政府动因无依据时标未知，推论的事实前提独立核验。
- [ ] 重要且有实质不确定性的推论已检验关键假设、合理反事实或有依据的竞争解释，并给能改变判断的信号；直接事实与低影响事项未为数量要求编造替代解释。
- [ ] 地缘政治分析区分言论、公布文件与实际执法；历史类比只生成假设。未来走向置信度与证据相称，没有决定论叙事。
- [ ] 方向允许中性或证据不足：中性有依据，证据不足未赋零分或自动归为利空。总体判断依据暴露和传导权重，不按政策数量投票。
- [ ] 量化结果使用真实输入、单位、计算方法和边界；预测或内部测算未伪装法规事实，脚本未被用来证明预测数字。

## 五、人工决策与交付审查

- [ ] 行动与实际风险/机会相连，责任角色、时限、依赖和验收标准清楚；无事项时不凑空矩阵或强制三项决策。
- [ ] 多事项需要时风险与机会分别排序，P0 解释为何不能等，P3 有触发器和复查日；紧迫度依据窗口与不可逆性，不替代置信度。
- [ ] 证据不足但潜在后果重大、窗口迫近时，核验/专业确认动作获得适当优先级，没有机械归 P3。
- [ ] 与公司暴露有关的低概率高影响尾部风险配有触发信号和相称预案；行动涉及的专业意见与依赖已列出。
- [ ] 单政策交付聚焦问题；扫描按实际法域与专题展开；更新明确基线、新增/修订/撤回及未复核的沿用内容，不将旧快照自动标为新时点已核验。
- [ ] 报告时点、必要时间范围与行政层级清楚，未覆盖部分已说明；资料不全时没有声称全球穷尽。
- [ ] 简短交付仍能找到 claim、来源和快照底稿；正式报告中的摘要、矩阵和正文没有互相矛盾或重复夸大。

## 六、信息与职责边界

仅使用授权内部资料，报告保留完成判断所需的敏感细节，不将内部合同、客户、收入、战略或未公开事项送到公开搜索。内部定位供授权读者复核，内部陈述不包装为公开事实，生成的旧报告不当作新证据自引。

本报告用于政策情报和经营决策参考；许可、处罚、诉讼、监管问询、重大交易与税务处理、数据跨境、制裁和出口管制等具体适用问题，列出需当地专业机构确认的事项。免责声明不能抵消未完成的必要检索。

输出跟随用户任务，默认 Markdown 或单政策对话答复；需正式文档、演示或图表时使用环境中相应能力，不强制先交完整扫描。用户样例仅用于结构与语气，不继承其中政策参数、公司事实或判断。

# 按模式组织 Markdown 交付

选择入口确定的模式，模板只用于组织真实内容。不要为了章节齐全扩大检索、重复同一判断或填空的 P0–P3、行政层级、情景表。

## 一、所有模式的最小信息

- 截止时点、文件版本或回看范围、适用法域与对象；前瞻区间仅在进行前瞻时列出。
- 判断及必要理由：利好 / 利空 / 中性偏利好 / 中性偏利空 / 中性 / 证据不足；影响程度与置信度分别说明，不能定向时不造净分。
- 事实、推论、假设与公司输入分别标明，正文 claim ID 对应 `claims.json`；原文引用附来源编号与条款/段落定位。
- 结论成立条件、实质例外与待确认事项，必要行动及其责任、时限；直接适用问题不强制宏观动因或多情景。
- 判断依据和重要证据缺口。核心证据覆盖按 core fact/inference 统计，简单答复可一行说明；X=0 写“不适用”。来源、快照与 ledger 可链接到底稿，详表不必复制进正文。
- 实际校验方式和人工复核状态；只有执行了 `--claims` 严格模式才能称为该模式通过，仍不证明判断正确。

相关统计与契约见 [claims-ledger.md](claims-ledger.md)，来源字段见 [evidence-and-sources.md](evidence-and-sources.md)。公开动态未检索到时说明查过的信源、查询词、时点与限制，并明示不代表不存在。

## 二、简单单政策

优先简短答复或事项卡片；用户要求存档时再按此结构保存。可合并短段，不强制表格。

```markdown
# [政策/适用问题]

> 截至：YYYY-MM-DD HH:MM；法域/对象：……；文件版本/状态：……

**判断**：……；影响程度：……；置信度：……

**原文与适用范围**：[P-F] …… [C1][S1]；关键条款/定位……
**公司含义**：分析推论…… [C2]；依赖的公司输入/假设…… [C3]
**条件与例外**：……
**必要动作**：……；责任角色……；时限……；依赖/验收……
**待确认与证据缺口**：……
**核验说明**：X 条核心 fact/inference 中 Y 条满足逐项可读 full L1/L2 快照门槛；严格校验/人工复核实际状态……
**可复核底稿**：来源链接、快照定位、claims.json……
```

直接条文事实不改写成推论；没有需要公司行动的事项时省略动作表，不编造待办。证据不足时说明尚能确认什么、不能确认什么，以及补证据路径。

## 三、完整扫描

先给管理层判断和决策窗口，再展开少量重点事项。公司背景和证据说明只写影响决策的部分；相关行政层级可在事项内说明，不必分别建立全球、国家、省州、市县四章。

# [公司/主题]政策与监管影响分析

> 信息截至：YYYY-MM-DD HH:MM
> 回看：YYYY-MM-DD 至 YYYY-MM-DD；前瞻：YYYY-MM-DD 至 YYYY-MM-DD
> 重点法域/业务：……；公司输入及未覆盖范围：……

## 四、更新

更新围绕基线差异，除非新增暴露或任务改变，不自动重做完整报告。

```markdown
# [公司/主题]政策判断更新

> 基线：报告/台账版本……，原截止日 YYYY-MM-DD
> 本次截止：YYYY-MM-DD HH:MM；本次复核范围……

**当前判断及是否变化**：……；关键原因……

| claim ID | 新增/修订/撤回 | 原判断 | 当前判断 | 新证据/原因 | 行动或优先级变化 |
|---|---|---|---|---|---|

**公司暴露变化与关键假设**：……
**沿用但未本次复核的内容**：claim ID、原核验日期、限制……
**下一步与监测**：动作、责任、时限；触发器与复查日……
**证据和校验说明**：核心覆盖；严格校验与人工复核状态；实质缺口……
**更新底稿**：修订后的 claims.json、对应快照和差异记录……
```

“未检索到新增动态”只描述本次实际检索结果；继承旧快照不证明政策仍有效。名单、法律状态或申报窗口等易变项重新复核；本次未复核部分不得标成截至新时点已核验。

## 五、写作取舍

第一屏回答决策问题；表格用于比较、排序与行动，正文解释传导、条件和不确定性。主张在首次完整表述处标 ID，摘要与详文不重复填 ledger。重要推论才展开竞争解释或反事实，不为篇幅增加背景。专业确认事项按实际风险列出，不用免责声明掩盖检索缺口。

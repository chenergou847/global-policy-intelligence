# 全球企业政策情报分析

回答发生了什么、如何传导到公司，以及当前应作何决策。分析深度随决策风险调整；“全球”是能力范围，不要求每次覆盖全部法域或行政层级。

## 选择模式

先复用用户给出的政策、公司信息和已有报告，选择以下模式。只读取本次需要的参考文件，不按固定七步加载全部资料。

| 模式 | 适用任务 | 执行与交付 |
|---|---|---|
| 简单单政策 | 一个文件、明确适用问题或范围明确的公司影响 | 核对原文、状态与适用范围，解释直接影响、条件和必要动作；交付简短答复或事项卡片，不扩展成全球扫描 |
| 完整扫描 | 多政策、多法域比较、市场准入或管理层综合决策 | 确定公司暴露与法域范围，检索重点信源，沿政策传导链评估并排序风险、机会和行动；仅展开相关专题 |
| 更新 | 已有报告、基线或监测台账的增量复查 | 先确认基线和截止日，复核受变化影响的证据及公司暴露；交付新增、修订、撤回判断和行动变化，未复核部分标明沿用日期 |

范围或公司信息不清时读取 [intake-and-scope.md](references/intake-and-scope.md)。扫描未指定时间范围时默认回看 3 个月、前瞻 6 个月，使用绝对日期；单政策以文件版本、有效状态和用户问题为准，更新以基线与新截止日为准。只补问会改变结论的关键事实；不足时写明最小假设和待确认项，仍可完成有边界的初步分析。

## 共通约束

- 公开政策事实须实际核验。分别记录来源权威等级 `L1–L5`、正文获取状态 `fetch_status`、法律状态和对具体主张的支持关系；`full` 不自动意味着权威、现行有效或结论正确。
- 核心 `fact` / `inference` 的每个 evidence URL 必须对应可读的 `full` 状态 L1/L2 正文快照。义务、罚则、门槛和生效日期优先回查 L1；L2 解释不替代法规明文。缺证据时撤下、缩小结论或列为待确认，不能只加“低置信度”后照写。
- 区分公开事实、分析推论、情景假设和公司输入。用户陈述或授权内部资料不自动成为公开事实；不将敏感经营信息发送到公开搜索，不引用此前生成的报告作为新证据。
- 官方动态“未检索到”不等于“不存在”。记录截止时间、实际查过的信源、查询词与阻断情况；仅就这些范围说明未检索到可由官方来源确认的动态。
- 结论方向可为利好、利空、中性偏利好、中性偏利空、中性或证据不足。中性需要充分依据；证据不足表示不能定向，不当作零影响。影响程度、置信度与管理紧迫度分别评估。
- 分析重点是 `政策/执法动作 → 目的与权限 → 行业/地方传导 → 公司主体、业务、资金、时间影响 → 条件、例外与失效点`。动因不明时写明未知；只对会改变重要决策的推论检验关键假设、合理反事实或有依据的竞争解释，不为直接明文事实凑替代解释。

## 校验与交付

正文使用稳定 claim ID 对应 `claims.json`，逐条列明证据 URL。严格校验契约为 `verify --claims claims.json`（`schema_version=1`）；完整字段、运行方式及能力边界以 [claims-ledger.md](references/claims-ledger.md) 为准。事实的引文、日期和数字只在该项所引证据中比对；推论须注明并引用依据，校验器不验证因果。`assumption` / `company` 不作为公开事实校验。严格模式未执行或工具不支持时如实披露，不能把旧校验通过称为严格核验完成。

交付前仍须人工复核证据是否支持主张、公司适用性、时效、推理和行动。脚本通过不能证明政策判断正确或扫描全面。发现缺口可交付明确标为初步、待确认或证据不足的结果，不宣称相关核心主张已核验。

简单单政策默认在对话中回答；完整扫描默认保存 Markdown，未指定位置时放当前项目 `.tmpfiles`，文件名包含主题和截止日；更新交付差异说明或修订报告。`claims.json` 与快照作为可复核底稿，可链接而无需全文塞入正文。所有模式都保留截止时点、适用范围、判断依据和实质证据缺口；覆盖统计、来源与检索过程按规模简写或放附录，不强制空章节。

按用户要求选择输出格式，正式文档排版使用当前环境可用的对应技能。本技能不替代当地法律、税务等专业意见；牌照、处罚、诉讼、申报、重大交易与税务处理的关键问题列为专业确认事项。用户样例只用于结构和语气，不继承其中参数、事实与结论。

# 全球企业政策情报分析

将政策变化转化为管理层可决策、公共事务可执行、法务与财务可复核的企业影响分析。重点回答两件事：**发生了什么、总体利好还是利空；公司接下来要做什么。** 坚持分析而非汇总的立场：每项判断都要有从证据到结论的完整论证链，并给出成立条件、例外和竞争解释。不把政策清单当作分析成果。

## 工作流程

七步顺序执行，不可跳步。政策分析是长任务，上下文被压缩后若不确定进度，回到本清单确认已完成到哪一步，再继续：

- [ ] 第一步：识别任务并校准范围
- [ ] 第二步：建立公司暴露与研究清单
- [ ] ⚠️ REQUIRED 第三步：按证据等级检索并核验
- [ ] 第四步：解释政策动因与传导
- [ ] 第五步：评估方向、影响和优先级
- [ ] 第六步：形成管理层报告
- [ ] ⛔ BLOCKING 第七步：交付前核查

### 第一步：识别任务并校准范围

判断任务是单项政策影响、区域扫描、多地区比较、市场准入、监管研判、风险/机会地图、管理层简报，还是既有报告更新。

开始新分析前读取 `references/intake-and-scope.md`，复用用户已经给出的信息，只补问会显著改变结论的公司运营事实和时间尺度。用户未指定时：

- 回看执行日前 3 个月的关键变化；重大存量事项不受此限制，但说明为何纳入；
- 前瞻执行日起 6 个月；重大长期事项可例外，但与半年内判断分开；
- 默认交付结构化 Markdown；
- 默认面向管理层和公共事务，同时给法务、财务可执行信息。

信息不足时不要假装已完成公司专属分析，也不要完全停住。列出最小假设和最多 3 个关键待确认问题，先提供边界清楚的“初步政策环境扫描”。

### 第二步：建立公司暴露与研究清单

围绕决策问题建立简明底稿：

- 主体：注册、持股、牌照、申报和合同主体；
- 业务：产品、服务、产业链位置、客户与商业模式；
- 地域：销售、生产采购、数据、员工、资金和政府关系所在地；
- 暴露：收入、成本、许可、供应链、政府客户、投资与税务；
- 时间：预算、交易、产品、合同、申报和政策窗口；
- 近期动态：只核验会改变政策暴露的公司变化。

先按实际暴露确定重点法域，不因“全球”而穷尽所有国家。跨国区域、国家、州省和市县区分别列出权限及传导关系，避免行政层级混写。

### ⚠️ REQUIRED 第三步：按证据等级检索并核验

本步骤不可跳过，也不可只用搜索结果摘要代替：没有经过实际核验的来源，后续所有判断都建立在不可靠的地基上。

开始检索前读取 `references/evidence-and-sources.md`。

1. 官方渠道优先、多轮检索：境内优先国家法律法规数据库、中国政府网和发布机关官网，境外优先官方公报、监管机构官网和国际组织官网；用法规全称、简称、文号与年份组合检索，无结果时更换官方术语或当地语言名称再试，不得以单轮检索失败得出“无动态”结论。
2. 再用政府实施指南、官方问答、发布会、官媒和国际组织文件解释政策目的与执行口径。
3. 高可信媒体、律所、行业协会和研究机构只作补充，重要结论尽量回溯原始来源。
4. 一般媒体和专家评论只作线索；匿名信息和社交媒体不得支撑核心事实。
5. 百家号、头条号、搜狐号、网易号、微信公众号、知乎、微博等平台自媒体与社评禁止写入来源台账和正文引用；命中时只从中提取原始文件线索并回溯 L1/L2 原文，回溯失败即弃用。识别特征与处理规则见 `references/evidence-and-sources.md`「禁止来源」。
6. 官方渠道查不到近期动态时，缩小议题或注明“近期无官方动态/未检索到可由官方来源确认的动态”，不得用社评凑数。
7. 对支撑核心结论的每个 L1/L2 来源，用网页读取工具实际打开原文，核对标题、文号、发布日期与生效日期后才可写入来源台账；打不开的链接按“未取得可核验原文链接”记录，并降低对应结论的置信度。

如用户授权了知识库，检索与公司战略、区域布局、经营暴露和既有政策判断有关的内部资料；命中后读取必要内容。不要将内部合同、收入、客户、战略或其他敏感信息作为外部搜索词。知识库未命中时如实说明。

将用户陈述、内部资料和公开事实分开；将法规明文、分析推论、情景假设和待确认项分开。结论强度不得高于证据强度。

### 第四步：解释政策动因与传导

形成判断前读取 `references/policy-analysis-framework.md`。

对每个高价值事项沿以下链条分析：

`政策或执法动作 → 官方目的 → 有证据支持的宏观/治理动因 → 政府层级与权限 → 行业和地方传导 → 公司主体、业务、资金、时间影响 → 条件、例外、失效点与待确认项`

明确区分政府公开说明与分析推论。不要把无法证实的政治动机写成事实。不要只复述政策条文；每项重点必须回答“为什么现在出台/收紧/放宽”和“为什么与这家公司有关”。

对高影响事项做关键假设检验，并给出至少一个有证据支持的竞争解释及其判别指标。

事项涉及地缘政治、国别政治生态、科技竞争与供应链重构或制裁与出口管制时，再读取 `references/geopolitics-and-tech-competition.md`：识别经济治国工具与科技竞争位置，用国别政治生态六维解释动因，沿传导链把局势落到公司暴露，并执行其中更严格的言论—行动分离与置信度上限纪律。

### 第五步：评估方向、影响和优先级

评估公司影响前读取 `references/impact-and-priority.md`。

先逐项判断，再汇总总体方向。总体结论必须使用以下之一：

- 利好
- 利空
- 中性偏利好
- 中性偏利空

同时给出影响程度和结论置信度，并按决策窗口与不可逆性确定管理紧迫度（即时决策 / 窗口内准备 / 跟踪观察）。不要按政策数量投票；依据业务暴露、影响强度、发生概率和时间窗口判断。数据充分时可量化，数据不足时使用高/中/低或区间，避免虚构精确金额和概率。

将合规风险与政策机会分开列账，并分别按 P0–P3 排序。每项行动写全：**动作、责任角色、时限、依赖、验收标准**。P0 说明为何不能等；P3 给触发器和下一复查日。

### 第六步：形成管理层报告

起草前读取 `references/report-template.md`。采用结论先行的分层结构，让管理层先看到方向和决策事项，再让公共事务、法务和财务追溯细节与证据。

重点事项使用“政策原文/官方口径 → 大白话 → 公司含义”的三级翻译，并写出：

`结论 → 成立条件 → 关键例外 → 失效点 → 待确认信息`

可按现实张力增加专题或删减不适用的普通章节，但不得省略：范围与证据说明、总体方向、优先级与紧迫度矩阵、P0–P3 风险和机会、行动计划、未来关注点、来源台账。

### ⛔ BLOCKING 第七步：交付前核查

核查未逐项通过前不得交付——这是防止虚构链接、日期、数字进入管理层视野的最后关口。

最终交付前读取 `references/quality-and-boundaries.md` 并逐项检查。优先删除低价值、低置信度材料，而不是为了篇幅保留噪声。任何无法核实的关键法规、日期、数字或公司动态均不得作为既定事实。

## 输出与职责边界

- 将最终报告保存为 `.md` 文件；默认放在当前项目的 `.tmpfiles`，文件名包含公司/主题和报告截止日。
- 用户要求在对话内审阅时，可同时展示管理层摘要；否则回复中仅说明总体判断、关键行动、待确认项和文件路径。
- 不直接生成或修改 Word。用户确认内容后，如需正式 Word，使用当前环境可用的 Word 转换技能（如 `docx`）完成排版。
- 本技能提供政策与经营影响分析，不替代当地执业律师、税务师或其他专业机构的正式意见。涉及牌照、处罚、诉讼、申报、交易结构或重大税务处理时，明确列出需专业确认的事项。
- 用户提供的样例只用于学习结构、语气和信息组织；其中公司、行业、地域、政策参数和既有结论均不得自动进入新报告。
